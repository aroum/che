# Спецификация двухпанельного файлового менеджера на базе архитектуры Yazi

Настоящий документ формализует требования к кроссплатформенному, высокопроизводительному двухпанельному файловому менеджеру (в стиле Midnight Commander и Far Manager), использующему архитектурные принципы и технологический стек Yazi (Rust, Ratatui, Tokio, Lua-расширения), но с адаптированным UX, логикой навигации и уникальной системой горячих клавиш.

## 1. Концепция и ключевые отличия от Yazi

В отличие от классического Yazi, использующего трехколоночную схему (Miller columns) и Vim-подобное управление, данный проект ориентирован на:

1. **Двухпанельный классический интерфейс** (Левая и Правая активные панели).

2. **Отказ от Vim-overload** в пользу интуитивной навигации без режимов (Normal/Visual/Insert) для базовых операций.

3. **Бескомпромиссную скорость** за счет асинхронного движка на Rust (Tokio) и эффективного рендеринга (Ratatui).

4. **Умный буфер обмена** и интеграцию с путями ОС.

## 2. Навигация и система хоткеев

Основной приоритет — убрать перегруженные Vim-последовательности, оставив клавиатуру максимально доступной для быстрого поиска и привычных действий.

### 2.1. Быстрый переход по буквам (Буквенный джамп)

- **Поведение по умолчанию:** Нажатие алфавитно-цифровой клавиши `[a-z, A-Z, 0-9]` (без модификаторов) инициирует мгновенный переход к файлу/папке, имя которой начинается с этой буквы.

- **Логика циклического перебора:**

  1. Первое нажатие `d` переводит курсор на первый элемент на букву `d` (например, `Documents`).

  2. Повторное нажатие `d` переводит курсор на следующий элемент на эту же букву (например, `Downloads`).

  3. Если файлы на букву `d` закончились, следующее нажатие возвращает курсор к первому файлу на букву `d`.

  4. Поиск регистронезависимый.

### 2.2. Навигация по панелям и каталогам

- `Tab` — переключение фокуса между левой и правой панелями.

- `ArrowUp` / `ArrowDown` — перемещение курсора вверх/вниз.

- `Backspace` / `LeftArrow` — переход на уровень вверх (в родительский каталог).

- `Enter`/`RightArrow` — вход в директорию/запуск файла.

## 3. Спецификация функций

### 3.1. Сортировка (Natural Sorting)

Файловый менеджер должен поддерживать естественную сортировку чисел в именах файлов (Natural Sort Order).

- _Стандартная сортировка:_ `1.txt`, `10.txt`, `2.txt`.

- _Естественная сортировка (опция по умолчанию):_ `1.txt`, `2.txt`, `10.txt`.

- Настройка должна переключаться через конфиг или меню сортировки.

### 3.2. Умная вставка и интеграция с путями (Smart Paste)

Логика работы клавиши вставки (`v` / `Ctrl+v`):

1. **Если внутренний буфер FM не пуст:**

   - Происходит стандартная вставка ранее скопированных внутри FM файлов в текущую директорию.

2. **Если внутренний буфер FM пуст, но в системном буфере обмена (ОС) есть текст:**

   - **Сценарий А (Прямой путь):** Если текст в системном буфере является валидным абсолютным или относительным путем (например, `~/.config/conf.toml` или `D:\Projects\app.log`), FM автоматически копирует этот файл/папку по указанному пути в текущую открытую директорию.

   - **Сценарий B (Шаблоны/Regex):** Если текст содержит регулярное выражение или wildcard (например, `/var/log/*.log`), FM находит все соответствующие файлы на диске и копирует их в текущую папку.

   - Перед выполнением такой вставки внизу экрана отображается краткий prompt-запрос для подтверждения: `Copy 5 files from /var/log/*.log? [Y/n]`.

### 3.3. Создание файлов и папок с таргетингом (`Alt`-модификатор)

Для ускорения работы без постоянных переключений панелей:

- Находясь в левой панели, пользователь нажимает `Alt + n`. Появляется prompt ввода имени файла. После подтверждения файл создается в правой (неактивной) панели. Это избавляет от необходимости делать `Tab` -> `n` -> `Tab`.

## 4. Архитектура фоновых задач и UX

Поскольку проект наследует производительность Yazi, операции ввода-вывода (I/O) должны быть полностью асинхронными и не блокировать интерфейс.

### 4.1. Прогресс-бар для операций

- Любая длительная операция (копирование, перемещение, архивация больших файлов) запускает фоновый воркер (Tokio task).

- В нижней части интерфейса (Statusline) или в отдельном плавающем окне отображается прогресс-бар:

  `[████████░░░░] 64% | 1.2 GB / 2.0 GB | 45 MB/s | ETA: 18s`

### 4.2. Очередь копирования/перемещения (Task Queue)

- По умолчанию операции выполняются параллельно (с ограничением на количество потоков для одного физического накопителя во избежание деградации скорости HDD/SSD).

- **Режим очереди:**

  - Возможность добавить задачу копирования в "отложенную очередь" (например, нажатием `Shift + C` вместо `c`).

  - Панель управления очередью (`q`), где пользователь видит список запланированных транзакций.

  - Кнопка запуска очереди на последовательное выполнение. Полезно при работе с медленными сетевыми дисками или USB-накопителями, где параллельное копирование снижает общую скорость.

## 5. Технический стек и переиспользование компонентов Yazi

Для обеспечения максимальной скорости работы и кроссплатформенности целесообразно использовать наработки экосистемы Yazi:

1. **Язык разработки:** Rust (гарантирует безопасность памяти, отсутствие GC-пауз и мгновенный запуск).

2. **Асинхронность:** `tokio` для многопоточного выполнения фоновых задач (I/O).

3. **Рендеринг интерфейса:** `ratatui` (проверенная библиотека для TUI).

4. **Конфигурация и плагины:** Использование встроенного интерпретатора Lua (как в Yazi) для кастомных плагинов, предпросмотра файлов и расширения функционала.

5. **Виртуальная файловая система:** Переиспользование эффективного механизма кэширования метаданных и рендеринга иконок из Yazi.
